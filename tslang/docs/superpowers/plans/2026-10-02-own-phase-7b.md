# `-mm=own` Phase 7b Implementation Plan: generators that borrow

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Under `-mm=own`, a generator over a parameter that holds a block compiles: `function*
each(a: number[]) { for (const v of a) yield v; }`. This is Rust's `fn each<'a>(a: &'a [f64]) ->
impl Iterator + 'a`. The state object is owned by the caller, but it borrows the argument, and
it may not outlive it. Then `.map`/`.filter`, which MLIRGen builds as such a generator over the
source array.

**Architecture:**

1. **The signature pass decides which fields of a state object borrow.** It is a module pass, and
   the per-function inference is parallel and cannot share state. It writes the decision as a
   module attribute that three places read:
   - the lowering, which builds the state object's release routine;
   - the inference in `next`;
   - the inference in callers.

   A state type is unique to its generator (its `next` field's type names a per-site
   `object_storage`), so a fact per type is a fact per generator.
2. **The lowering** skips a borrowed field in the state object's release routine. For a borrowing
   `.captured` box, it calls a box routine that frees each cell but not what the cell holds.
3. **The maker's result is bounded by its arguments**: `__own_result_bounded = [indices]`. This is
   not `__own_result_borrows`, which means "the result is a borrow" (no release, not fresh).
   Bounded means owned (fresh, released as usual) and tenured: no use of the result may run
   after an end of a bounding argument, and the result may not be stored, returned or captured.

**Spec:** §18.6 (this phase's input). Results go into §19.

## Shapes (measured on af7b150f)

- **The maker** of `each(a: number[])`:
  1. `a`'s cell is `ts.Variable(%arg0) {captured}` (not owning), `ts.RetainCell`ed.
  2. It is stored into the box `ts.Variable {captured, __capture_box}`, which is `ts.RetainCell`ed
     and stored into `.captured` of the initial state.
  3. The frame's `ts.ReleaseCell(cell)` follows.

  Today this is 5b's "its value is the caller's".
- **`next`** reads the cell out of the box (`ts.Load(ts.PropertyRef(box, i))`). The `for...of`
  copies the array into a state field `.a`: `ts.Retain(v)`, `ts.Store(v, PropertyRef(state, .a))`.
- **The caller** keeps the generator in an owning `let` and calls `next` through it, as in 7a.
- **`.map(f)`**: the caller builds a closure whose box holds a copy of the source array (rc
  `ts.Retain`s it) and the callback, and calls it at once (devirtualized `ts.SymbolCallInternal`).
  That closure body (`..iter`) is the maker. It copies its box's fields into a new box (another
  `ts.Retain`) and stores that box into the state object.

## Rulings made while planning

- **A borrowing field**, for a generator state type `T` (it has a `next` in `fieldFunctions`) whose
  maker `M` is closed (private, every caller known):
  - **The box.** The `.captured` box borrows when every cell `M` fills it with is a parameter's
    cell. Its cells then move into the box, which frees them and not their values.
  - **A state field `p`** borrows when every store into `p`, anywhere in the module, stores a
    value rooted at a read of a borrowing cell or of another borrowing field. This is computed as
    a fixpoint. One store of anything else, and `p` owns as today.
- **`M`'s result is bounded** by each parameter whose cell holds a block and goes into a borrowing
  box. `__own_result_bounded` is pinned on `M` and on each call that resolves to it.
- **At a call with a bounded result**, the result is fresh, and owned by whatever holds it, as
  today. Every use of it, followed through views and the `let`s that hold it, may not be reachable
  after any end of a bounding argument's root:
  - its releases;
  - an assignment to it;
  - a drop of the place it was read from.

  A use that keeps the result (a store into a container, a return, a capture) is an error. Cost if
  wrong: a generator that reads its argument after the caller freed it.
- **In `next`:**
  - a store into a borrowing field erases rc's retain and takes nothing;
  - a `ts.ReleaseSlot` of a borrowing field frees nothing (`__own_slot_borrows`, read by the
    lowering, as `__own_cell_borrows` is);
  - a read of a borrowing cell or field is a borrow with no end in `next`, as a parameter cell's
    is in 5a.
- **Phasing:** 7b-1 is tasks 1-4 (parameters). 7b-2 is task 5 (`.map`/`.filter`). Yielding a borrow
  stays a limit: the result record type `{value: C, done}` is shared between generators, so a fact
  per type does not work for it.

## Review Focus

1. A field is marked borrowing only when nothing but borrows is ever stored into it.
2. The bounded check follows every derived use of the result, and treats anything it does not
   know as a keep.
3. An open maker gets no facts, and stays the 5b error.

  `own_err_generator_bounded_stored`: a store is the same keep check as the return.
