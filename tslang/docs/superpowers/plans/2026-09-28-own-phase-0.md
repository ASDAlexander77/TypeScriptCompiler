# `-mm=own` Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** `-mm=own` exists, and a program whose every heap block has a single owner compiles,
runs, reclaims with no reference counting, and is measured. Any other ownership shape is a
compile error at its source location.

**Architecture:** MLIRGen is not touched. It keeps emitting rc's ownership ops.
A new `OwnershipInferencePass` runs at the affine level under own only. In phase 0 it knows one
verdict, the *birth take* (the move of a fresh value into its one owner): it erases that
retain and reports every other retain as an error. Lowering under own keeps every release but
makes it destroy-shaped: a header load, an immortal check, then destroy, with no count
arithmetic. A retain that survives to lowering is a backstop error.

**Tech Stack:** C++17, MLIR/LLVM (tslang's LLVM 19 tree), CMake/ctest, the
`test/tester/test-runner.cpp` harness, PowerShell for the measuring script.

**Spec:** `docs/superpowers/specs/2026-09-24-own-memory-model-design.md`. Read §2, §3 and all of
§10 first: §10 amends §3.4, §3.5 and §7 phase 0, and this plan follows the amendments.

## Global Constraints

- The `-mm=` spelling is `own`, and `memoryModelName(MemoryModelOwn)` returns `"own"`. That name
  also forms the shared-library marker `__tsmm_own_<file>_<hash>`.
- `gc`, `rc` and `none` output must not change by a single instruction. Everything new is behind
  `memoryModel == MemoryModelOwn`, or behind `tracksOwnership()` where rc behaviour is unchanged
  by construction.
- Never branch on the memory model in MLIRGen (spec §4.3). The four `isRefCounted()` sites in
  MLIRGen become `tracksOwnership()`: under own they must emit exactly what they emit under rc.
- `needsGCRuntime()` stays false for own: allocate through `malloc` as rc does. `_MemoryAlloc`
  keeps its header store of 0 under own (spec §10.4).
- `__tslang_inc_ref` and `__tslang_dec_ref` never appear in own output.
- Own tests run with `--no-default-lib`, as rc's do (spec §10.3).
- Build: `cmake --build __build/tslang/windows-msbuild-2026-release --config Release --target tslang`
  (add `test-runner` when the runner changes). Test: from that directory, `ctest -j 16 -C Release`.
  A bare `ctest` reports every test as "(Not Run)".
- Do not edit `TypeScriptOps.td`, since phase 0 adds no ops. If a task seems to need it, stop and ask.
- Commits are GPG-signed. On a signing timeout, retry, and never pass `--no-gpg-sign`.
- Every commit message ends with the `Co-Authored-By:` line the session gives.
- Branch `own-phase-0` off `origin/main` with `git checkout --no-track -b own-phase-0 origin/main`.
  It needs PR #398 (an error diagnostic fails the compile) merged first. Without #398 the
  backstop in Task 4 prints an error and ships the program anyway.

## Review Focus

1. **A release with no acquisition.** rc tolerates one: a block released from count 0
   underflows to `HEAP_BLOCK_IMMORTAL` and leaks. Under own the same release destroys, so a
   latent rc over-release becomes a use-after-free. Task 5's pass reports a `ts.Release`,
   `ts.ReleaseSlot` or `ts.ReleaseCell` whose value or slot has no acquisition in the function
   and no birth (see "released but never taken" in Task 5). Task 6 has a negative test for it.
2. **A fresh value with two owners.** `const a = [1]; const b = a;` has a `ts.Variable` for `b`
   whose initializer is a load of `a`, and rc retains that load. The retain's operand is not
   fresh, so it is an error. Task 6 has this as a negative test, and it must never compile.
3. **A value that leaves the function.** `return new C()` retains before returning, which is
   rc's retaining-return convention. The caller consumes the result through `__owned_result`.
   Both halves must stay balanced: Task 6's `own_return_new.ts` returns a fresh instance 1M
   times and is measured flat.
4. **Unwind paths.** A birth-taken local released on the unwind edge of a `try` must be released
   once on each path, not twice on the path that throws. Task 6's `own_try_local.ts` throws
   through a function holding a fresh array and is run 100k times under the measuring script.
5. **An unknown producer.** A heap value returned by a runtime helper, or by an imported
   function, has no `__owned_result` and is not an allocating op, so it is not fresh. A retain of
   it must be an error, never a birth take. Task 6's negative test `own_err_unknown_producer.ts`
   uses `.slice()` on an array (a runtime-helper result) and holds it in a local.

## Task 5: `OwnershipInferencePass`, phase 0: the birth take

**Files:**

- Create: `lib/TypeScript/OwnershipInferencePass.cpp`

**Interfaces:**

- Consumes: `OWNED_RESULT_ATTR_NAME`, `OWNED_LOCAL_ATTR_NAME` and
  `OWNED_LOCAL_CONSUMED_ATTR_NAME` from `include/TypeScript/Defines.h`, and `MemoryModelOwn`.
- Produces: `std::unique_ptr<mlir::Pass> mlir::typescript::createOwnershipInferencePass();`, a
  `TypeScriptFunctionPass`. After it runs without error, the function has no `ts.Retain`,
  `ts.RetainSlot` or `ts.RetainCell`.

**The phase-0 rule.** rc's count for a block is its births plus its retains. The pass erases a
function's retains of a value only when that count provably never exceeds one, which makes
the single release that rc already emits the owner's destroy. For a heap-typed SSA value `V`:

- `V` is **fresh** when its defining op is one of `ts.New`, `ts.CreateArray`, `ts.NewArray`,
  `ts.StringConcat` or `ts.CharToString`, or carries `OWNED_RESULT_ATTR_NAME`. String `+`
  reaches the affine level as `ts.ArithmeticBinary {__owned_result}`, and number-to-string as
  `ts.Cast {__owned_result}`, so both are fresh through the attribute. These are the
  lowerings that allocate (checked with `LowerToLLVM.cpp`'s `MemoryAlloc` users on #397), plus
  the ops rc already marks as "arrives with a reference".
- `V`'s **birth** is 1 when its defining op carries `OWNED_RESULT_ATTR_NAME` *and* is a call
  (`ts.Call`, `ts.CallIndirect`, `ts.CallInternal`). The callee retained on its way out (rc
  §9.24), and the receiver consumed it. Otherwise the birth is 0. `markFreshStringOwned` marks a
  string and emits the retain that *is* its birth, so that retain is counted below as an
  acquisition.
- `V`'s **acquisitions** are its birth, plus every `ts.Retain` whose operand is `V`, plus every
  `ts.RetainSlot` on a `ts.Variable` whose initializer is `V`.
- **Birth take:** `V` is fresh and its acquisitions total exactly 1. Erase those retains.
- **Anything else is an error**, at the retain's location. The error is
  `"'<name>' takes a second reference; -mm=own cannot prove a move or a borrow here yet"`. Use
  the `ts.Variable`'s name when the retain is a `RetainSlot`, and "this value" otherwise. Every
  `ts.RetainCell` is an error: `"closures that capture a heap value are not supported by -mm=own yet"`.
- **A `ts.RetainSlot` on a variable with no initializer** is an error in phase 0. Its storage was
  hoisted in front of a `try`, and its initializing store stayed at the declaration
  (`LowerToLLVM.cpp:2380`). Phase 1 follows the store. The error is known to reject an owned
  local declared inside a `try` body.
- **A fresh value with a retain and no `ts.Release`** is not an error and not a hazard. On
  2026-09-28, `const s = "item " + i` was folded into its SSA value (`ts.ArithmeticBinary
  {__owned_result}` + `Retain`), and no release was visible at the affine level. The rule
  bounds acquisitions only, so a missing release can leak but never double-free. Task 7's
  measurement is where such a leak shows.
- **Released but never taken:** a `ts.ReleaseSlot` whose slot is a `ts.Variable` with no
  acquisition (no `RetainSlot`, no `OWNED_LOCAL_CONSUMED_ATTR_NAME`, not fresh-initialized) is an
  error `"'<name>' is released but never owned"`. Skip it when it is the hand-over half of an
  overwrite, reusing `OwnershipVerifierPass::isHandOver`'s test: move that function into a
  small shared header `include/TypeScript/OwnershipOps.h` and include it from both passes.

```cpp
#include "mlir/Pass/Pass.h"

#include "TypeScript/TypeScriptDialect.h"
#include "TypeScript/TypeScriptOps.h"
#include "TypeScript/TypeScriptFunctionPass.h"
#include "TypeScript/Passes.h"
#include "TypeScript/Defines.h"
#include "TypeScript/OwnershipOps.h"

#include "llvm/ADT/DenseMap.h"
#include "llvm/ADT/SmallVector.h"

#define DEBUG_TYPE "own"

namespace mlir_ts = mlir::typescript;

namespace
{

// Ownership inference for -mm=own, phase 0. See
// docs/superpowers/specs/2026-09-24-own-memory-model-design.md, section 10.6.
//
// rc's count for a block is its births plus its retains. Where that provably never exceeds one,
// the block has one owner, the release rc already emits is that owner's destroy, and every
// retain on the way is erased. Anything else is reported: phase 0 knows no other verdict.
class OwnershipInferencePass : public mlir::PassWrapper<OwnershipInferencePass, TypeScriptFunctionPass>
{
  public:
    MLIR_DEFINE_EXPLICIT_INTERNAL_INLINE_TYPE_ID(OwnershipInferencePass)

    void runOnFunction() override
    {
        auto f = getFunction();

        // value -> the retain ops that acquire it (Retain on the value, RetainSlot on the
        // variable it initializes)
        llvm::DenseMap<mlir::Value, llvm::SmallVector<mlir::Operation *, 2>> acquirers;
        llvm::SmallVector<mlir::Operation *> unattributed;
        llvm::SmallVector<mlir_ts::ReleaseSlotOp> slotReleases;

        f.walk([&](mlir::Operation *op) {
            if (auto retainOp = mlir::dyn_cast<mlir_ts::RetainOp>(op))
            {
                acquirers[retainOp.getReference()].push_back(op);
            }
            else if (auto retainSlotOp = mlir::dyn_cast<mlir_ts::RetainSlotOp>(op))
            {
                auto varOp = retainSlotOp.getSlot().getDefiningOp<mlir_ts::VariableOp>();
                if (varOp && varOp.getInitializer())
                {
                    acquirers[varOp.getInitializer()].push_back(op);
                }
                else
                {
                    unattributed.push_back(op);
                }
            }
            else if (mlir::isa<mlir_ts::RetainCellOp>(op))
            {
                op->emitError("closures that capture a heap value are not supported by -mm=own yet");
                signalPassFailure();
            }
            else if (auto releaseSlotOp = mlir::dyn_cast<mlir_ts::ReleaseSlotOp>(op))
            {
                slotReleases.push_back(releaseSlotOp);
            }
        });

        for (auto *op : unattributed)
        {
            reportSecondReference(op);
        }

        llvm::SmallVector<mlir::Operation *> toErase;
        for (auto &[value, retains] : acquirers)
        {
            auto total = birth(value) + retains.size();
            if (isFresh(value) && total == 1)
            {
                toErase.append(retains.begin(), retains.end());
                continue;
            }

            for (auto *op : retains)
            {
                reportSecondReference(op);
            }
        }

        for (auto releaseOp : slotReleases)
        {
            auto varOp = releaseOp.getSlot().getDefiningOp<mlir_ts::VariableOp>();
            if (!varOp || mlir_ts::isHandOver(releaseOp))
            {
                continue;
            }

            auto init = varOp.getInitializer();
            auto owned = varOp->hasAttr(OWNED_LOCAL_CONSUMED_ATTR_NAME) || (init && acquirers.count(init));
            if (!owned)
            {
                releaseOp.emitError("'") << varName(varOp) << "' is released but never owned";
                signalPassFailure();
            }
        }

        for (auto *op : toErase)
        {
            op->erase();
        }
    }

  private:
    static bool isFresh(mlir::Value value)
    {
        auto *def = value.getDefiningOp();
        if (!def)
        {
            return false; // a block argument: a parameter, or a value merged from branches
        }

        return def->hasAttr(OWNED_RESULT_ATTR_NAME) ||
               mlir::isa<mlir_ts::NewOp, mlir_ts::CreateArrayOp, mlir_ts::NewArrayOp, mlir_ts::StringConcatOp,
                         mlir_ts::CharToStringOp>(def);
    }

    // 1 when the value arrived with a reference the callee took (the retaining return, rc
    // §9.24); 0 otherwise - including a string marked by markFreshStringOwned, whose birth is
    // the retain MLIRGen emitted beside the mark and is counted as one of its acquisitions.
    static unsigned birth(mlir::Value value)
    {
        auto *def = value.getDefiningOp();
        return def && def->hasAttr(OWNED_RESULT_ATTR_NAME) &&
                       mlir::isa<mlir_ts::CallOp, mlir_ts::CallIndirectOp, mlir_ts::CallInternalOp>(def)
                   ? 1
                   : 0;
    }

    static llvm::StringRef varName(mlir_ts::VariableOp varOp)
    {
        // the name MLIRGen gave the declaration, when it kept one
        if (auto nameLoc = mlir::dyn_cast<mlir::NameLoc>(varOp.getLoc()))
        {
            return nameLoc.getName().getValue();
        }

        return "this value";
    }

    void reportSecondReference(mlir::Operation *op)
    {
        llvm::StringRef name = "this value";
        if (auto retainSlotOp = mlir::dyn_cast<mlir_ts::RetainSlotOp>(op))
        {
            if (auto varOp = retainSlotOp.getSlot().getDefiningOp<mlir_ts::VariableOp>())
            {
                name = varName(varOp);
            }
        }

        op->emitError("'") << name << "' takes a second reference; -mm=own cannot prove a move or a borrow here yet";
        signalPassFailure();
    }
};

} // end anonymous namespace

#undef DEBUG_TYPE

{

}
```
