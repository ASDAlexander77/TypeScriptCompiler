# `-mm=own` Phase 5 Implementation Plan: closures

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Under `-mm=own`, a closure that captures a variable compiles when its ownership can be
proven (spec §2.5, §4.2 step 6). Today every `ts.RetainCell` is the error "closures that capture a
variable are not supported by -mm=own yet" (25 corpus files stop there first), and a captured
parameter with a heap value is a lowering error.

After this phase:

- A closure that does not escape **borrows** what it captures. The frame keeps its cells, the box
  owns nothing but itself, and the closure may not run after anything it borrows is released.
- A closure that escapes (returned, stored, pushed, kept) **owns** what it captures. Its cells
  and by-value captures move into the box, and the frame may not use them after that.
- Everything else is an error, with the rule in the message.

**Architecture:** inference-side only, plus two marks the lowering reads. MLIRGen does not change
(`test-own-mlirgen-matches-rc` keeps passing).

1. **`OwnershipInferencePass`** classifies each `ts.CreateBoundFunction {__owns_capture}`: does its
   value escape? Then it decides each capture: a cell (a captured `ts.Variable`, or a cell an
   enclosing closure captured, read out of its box) or a by-value copy (`ts.Store` of a value into
   a box field, after rc's `ts.Retain`).
2. **Two marks for the lowering**, own only:
   - `__own_borrows_captures` on `ts.CreateBoundFunction`: the box's tag names a routine that
     frees the box and nothing it holds.
   - `__own_cell_borrows` on `ts.ReleaseCell`: the cell does not own its value (a captured
     parameter, `this`), so its release frees the cell only.
3. **Drops** learn cells: an assignment to a captured variable, in the frame or in a closure body,
   may destroy what a borrow read out of it. A call given a closure may run it.

**Tech Stack:** C++17, MLIR, CMake/ctest, `test/tester/test-runner.cpp`,
`test/tester/tools/measure.ps1`.

**Spec:** `docs/superpowers/specs/2026-09-24-own-memory-model-design.md`: §2.5 (closures), §4.2
step 6, §15.7 (this phase's input). Results go into §16.

## Shapes (measured on 7c543604)

- **The closure** is `V = ts.CreateBoundFunction(B, @f) {__owned_result, __owns_capture}` followed by
  rc's `ts.Retain(V)`: a fresh value, moved or released like any other. `B` is the box,
  `ts.Variable {captured, __capture_box}`, filled by `ts.Store(x, ts.PropertyRef(B, i))`.
- **A call of a folded `const f`** is devirtualized to `ts.SymbolCallInternal(B) @f`: the box is
  used without `V`. A call through a value is `ts.CallInternal(ts.GetMethod(V), ts.GetThis(V))`. A
  closure passed on is `ts.Cast(V)` to `!ts.hybrid_func`: the same `{func, this, tag}` triple.
- **A cell** is `ts.Variable(init) {captured}`: `__owned`/`__owned_consumed` when the frame owns the
  value, nothing for a parameter's (`this` included) or for a value that owns no heap. rc:
  `ts.RetainCell(cell)` before the box store, `ts.ReleaseCell(cell)` at the frame's scope exit; the
  box's release routine (`tsrelcb_`) releases every cell field (value, then cell) and every
  by-value field. Under own, today's `tsrelcb_` destroys all of it.
- **A cell inherited by a nested closure** is `ts.Load(ts.PropertyRef(%arg0, i))` of type `!ts.ref<T>`
  in the enclosing closure's body, `ts.RetainCell`ed for the inner box.
- **A by-value capture** (a folded `const`) is `ts.Retain(x)` then `ts.Store(x, ts.PropertyRef(B, i))`.
- **An assignment to a captured variable** is `ts.ReleaseSlot(cell)` + `ts.Store(new, cell)` in
  the frame, and `ts.ReleaseSlot(ts.Load(ts.PropertyRef(%arg0, i)))` + `ts.Store` in a closure body.
  Neither is in the inference's `drops`, nor in the signature pass's `dropsInBody`.
- **A loop** re-creates the box each iteration, releases the closure at the iteration's end, and
  releases the cells after the loop.

## Rulings made while planning

- **Escape is decided on `V`'s flow, before anything else.** `V` does not escape when every use,
  through function-type casts and owning `let`s (their loads), is rc's bookkeeping, a borrow
  (`isBorrow`: a call's argument the callee does not keep, `ts.GetThis`/`ts.GetMethod`), or a call.
  Anything else escapes: a return (a store into the result slot), a store into a field, element,
  global or another box, a push, a kept argument, a boxing cast. Cost if wrong: an escaping
  closure read as borrowing would free its cells at the frame's exit, so anything unknown is an
  escape.
- **A non-escaping box borrows everything; an escaping box owns everything.** Mixing per field
  would need a routine per closure site. Cost: a non-escaping closure cannot take ownership of a
  value it is given; none needs to.
- **The closure's uses** are every use of `V` (through casts and owning `let`s) and of `B` (other
  than its own fill and `V`'s creation). A borrowing closure's uses may not run after an end of
  anything it borrows:
  - a cell this frame owns: its `ts.ReleaseCell`s, and the point it moves into an escaping box;
  - a by-value fresh value: its releases and takers;
  - a parameter's cell, an inherited cell, a parameter: nothing ends in this frame.
  A by-value copy of a borrow (`const c = h.c; () => c.x`) is a store of a borrow: an error, as
  today (`cannot be stored, returned or captured`). Recorded as a limit.
- **A captured parameter's cell borrows its value.** Its `ts.ReleaseCell` frees the cell only
  (`__own_cell_borrows`), and nothing may assign it: not the frame, not any closure body that holds
  the cell, followed through nested captures. The lowering's "a captured variable cannot own its
  value under -mm=own yet" goes. Cost if wrong: a parameter freed under its caller.
- **Cells are places.** `ts.ReleaseSlot` of a cell is a drop of every chain whose root this
  function does not own (a read of a cell is such a root). In the signature pass the same op makes
  a function drop: the cell is reachable from its creator.
- **A call given a closure may run it.** A call with an operand that is a closure value, a capture
  box, or derived from one, drops every chain when its callee may drop: the box may hold anything.
  Cost: spurious errors where a closure that cannot drop is passed to an unknown callee.
- **An escaping capture is a move of each cell into the box** (5b). The `ts.RetainCell` is the
  move: the frame's `ts.ReleaseCell`s it reaches must be dominated by it and are erased; a frame
  use of the cell reachable after it is a use after move; a second capture reachable after it is
  too; a capture in a loop of a cell declared outside is moved in a loop. A parameter's cell with
  a heap value and an inherited cell cannot move: an error. A cell holding a number can. Spec
  §2.5's "any use after the closure's creation" is this rule.
- **Phasing.** 5a: non-escaping closures, parameter cells, the drop rules; an escaping closure is
  `a closure that escapes is not supported by -mm=own yet`. 5b: escaping closures. One PR each.

## Review Focus

1. Escape classification: any use of `V` the classifier does not recognise must be an escape.
2. A borrowing box's routine frees the box only; an owning box's routine is today's `tsrelcb_`.
3. Every `ts.ReleaseCell` of a cell whose value is a parameter's carries `__own_cell_borrows`, or the
   compile fails.
4. The three drop holes: a frame assignment to a captured variable, a closure body's, and a call
   that runs a closure assigning a field of a by-value capture. Each has a negative test.
