# `-mm=own` Phase 3 Implementation Plan: containers and unions

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Under `-mm=own`, a value read out of a field or an element is a *borrow* bounded by its
container (spec §2.3), and a union or optional local is a view of the block it holds. Today:

- `const c = h.c; h.c = new C(5); c.x` compiles and reads freed memory. So do an element store,
  an assignment of `h`, and a call given `h` between the read and the use. rc has the same bug.
- `let c = h.c` and `let e = arr[i]` are rejected ("takes a second reference").
- `let u: C | null = new C(1)`, `let u: C | string = new C(1)` and `let u: C | undefined = ...`
  are rejected, the most common shape in the probes.
- `h2.c = h.c` is rejected with the unhelpful "takes a second reference".

After this phase, the first becomes an error, the second and third compile, and the fourth says
why.

**Architecture:** Only `lib/TypeScript/OwnershipInferencePass.cpp` changes.

1. **Views.** An op whose result is the same block as its operand - a widening or narrowing
   `ts.Cast` between class, union and optional types, `ts.CreateUnionInstance`,
   `ts.GetValueFromUnionOp`, `ts.OptionalValue`, `ts.Value` - is transparent. Every place the
   pass identifies a value strips views up to the root (`rootOf`), and every place it lists a
   value's uses looks through views down to the real users (`usesThroughViews`).
2. **Place reads.** A `ts.Load` of a heap-owning value through a `ts.PropertyRef` or
   `ts.ElementRef` is a borrow of that place. It never owns: it may not be retained, stored,
   pushed or returned. No use of it, or of anything derived from it, may be reachable from a
   *drop* of its chain without passing back through the read:
   - an overwrite (`ts.ReleaseSlot`) of any place on the chain, matched by position and type;
   - an `ArrayPop`/`ArrayShift`/`ArraySplice`/`SetLengthOf` of an array whose elements are on the
     chain;
   - an end of the chain's root: its releases, assignments, and moves;
   - a call that may reach the root.
3. **`let` receivers of a place read** borrow it: their `ts.RetainSlot` and `ts.ReleaseSlot`s go,
   exactly as phase 2's borrows, and their reads join the read's uses.

**Tech Stack:** C++17, MLIR, CMake/ctest, `test/tester/test-runner.cpp`,
`test/tester/tools/measure.ps1`.

**Spec:** `docs/superpowers/specs/2026-09-24-own-memory-model-design.md`. Read §2.2 (dropping
mutations), §2.3, §4.2 step 5, §5 (borrow rows), and §13 (phase 2 as built; §13.5 is this
phase's input).

## Rulings made while planning

- **`any` boxing moves to phase 4.** §7 lists it under phase 3, but unboxing is a call to a
  generated `___unbox<T>` that retains the payload inside and returns it +1, and `___cast<U, T>`
  allocates on one branch and returns the payload on the other. Making either a borrow is phase
  4's borrowed-from-argument result, a callee fact; special-casing the helpers by name here would
  be thrown away there. A found rc bug belongs with it: `const a: any = new C(i)` never releases
  the box (`measure.ps1`: rc 66.2 MB, gc 6.1 MB over 1M iterations) - the boxing cast is +0 and a
  folded `const` takes no reference. Cost if wrong: phase 3 ships without `any`.
- **Calls and roots this function does not own.** A place read whose root is a parameter, `this`,
  a global or any value the function did not make is dropped by *every* call: the caller's owner
  may be a global the callee assigns. Sound, and restrictive for methods
  (`const c = this.c; this.log(); c.x` becomes an error) until phase 4's callee facts. A root the
  function owns is dropped only by a call given something derived from the root and not from
  the read itself: `f(h)` drops `h.c`, `f(c)` does not. Cost if wrong: methods that compile today
  (unsoundly) are rejected.
- **Aliasing.** An overwrite hits a place on the chain when its `ts.PropertyRef` has the same
  position and result type, or its `ts.ElementRef` the same result type. Two references to one
  field of one object always agree on both, and a derived class keeps its base's positions, so
  the match is sound; it may also match an unrelated class's field of the same type at the same
  position, which can only add an error. Cost if wrong: extra errors.
- **Merges.** A value merged from branches (`u ?? d`, a conditional) arrives as a block argument
  and stays unsupported. §14 lists it.

## Review Focus

1. `for (const e of arr) { out.push(e.x); arr.push(new C()) }`: pushing onto the array being
   iterated must stay accepted (a push drops nothing). Covered by `own_element_borrow`.
2. A field read inside a loop that overwrites the field at the end of the body must stay
   accepted: the next iteration's read is a new borrow. Covered by `own_container_loop`.
3. Temporaries: `h.c.x`, `arr[i].v.length` and `this.items.length` are place reads too. Every
   existing own test and the corpus must not regress through them. The corpus report before and
   after (Task 4) shows it.
4. A borrow of an element must end at a `pop`, including one in a nested block and one in a
   `for...of` body. Covered by `own_err_element_read_popped` and `own_err_element_read_loop_pop`.
5. Views must be stripped at *every* site that identifies a value: candidates, `retainedValue`,
   `movesOf`, `takerOf`, `takerAcquires`, `acquirePoint`, `isFresh`, `isImmortalLiteral`,
   `slotLoadOf`, `readUsedAfter`, and `tryBorrow`'s walk. One missed site is a spurious error or,
   worse, a release that is not erased when the value moved. Each union positive test is also a
   teeth test.

- [ ] **Step 3: Implement the views**

```cpp
    // An op whose result is the very block its operand holds: a class widened to a union or an
    // optional or narrowed back, a union made from its payload or read back from it. rc's retain
    // or release of either is one of the block, so the pass looks through them. A cast that
    // converts (a number printed into a string) or boxes (into `any`) makes a new block and is
    // not one.
    static bool isView(mlir::Operation *op)
    {
        if (mlir::isa_and_nonnull<mlir_ts::CreateUnionInstanceOp, mlir_ts::GetValueFromUnionOp,
                                  mlir_ts::OptionalValueOp, mlir_ts::ValueOp>(op))
        {
            return true;
        }

        auto castOp = mlir::dyn_cast_or_null<mlir_ts::CastOp>(op);
        if (!castOp)
        {
            return false;
        }

        auto keeps = [](mlir::Type type) {
            return mlir::isa<mlir_ts::ClassType, mlir_ts::UnionType, mlir_ts::OptionalType>(type);
        };
        return keeps(castOp.getIn().getType()) && keeps(castOp.getType());
    }

    // The block a value is a view of.
    static mlir::Value rootOf(mlir::Value value)
    {
        while (auto *def = value.getDefiningOp())
        {
            if (!isView(def) || def->getNumOperands() == 0)
            {
                break;
            }

            value = def->getOperand(0);
        }

        return value;
    }

    // Every user of `root` and of the views of it, with the value it uses. A view itself is not a
    // use.
    static void forEachUse(mlir::Value root, llvm::function_ref<void(mlir::Operation *, mlir::Value)> each)
    {
        llvm::SmallVector<mlir::Value> values{root};
        while (!values.empty())
        {
            auto value = values.pop_back_val();
            for (auto &use : value.getUses())
            {
                auto *user = use.getOwner();
                if (isView(user) && use.getOperandNumber() == 0)
                {
                    values.push_back(user->getResult(0));
                    continue;
                }

                each(user, value);
            }
        }
    }
```

Then, at each site:

- `runOnFunction` candidates: insert `rootOf(...)` of a Retain's and a Release's operand and of a
  Variable's initializer; skip a fresh result that is a view (`isView(op)`), whose root is its
  candidate.
- `retainedValue`: return `rootOf(...)`.
- `checkValueMoves` and `movesOf`: collect users with `forEachUse(value, ...)`, calling
  `isBorrow(user, used)` with the used value.
- `takerOf`: the same over `forEachUse`.
- `takerAcquires` and `acquirePoint`: a `ts.Retain` of `value` or of any view of it counts.
  Collect the retains with `forEachUse`.
- `isImmortalLiteral`: apply to `rootOf(value)`. `isFresh` is only ever asked about roots.
- `slotLoadOf`: step through `isView` ops, not only class/union/optional casts. It keeps the
  current behaviour for those casts.
- `readUsedAfter` and `tryBorrow`'s walk: follow a view's result as the same borrowed value,
  where they follow a `ts.CastOp` now. In `tryBorrow`, a cast that is *not* a view (to `boolean`
  in `if (b)`) keeps its current treatment: a non-borrowed derived value.

- [ ] **Step 3: Implement**

```cpp
    // A read of a heap value out of a field or an element: `h.c`, `arr[i]`. It does not own what
    // it reads - the container does - so it can only be a borrow (spec 2.3).
    mlir_ts::LoadOp placeReadOf(mlir::Value value)
    {
        auto loadOp = rootOf(value).getDefiningOp<mlir_ts::LoadOp>();
        if (!loadOp || !ownsHeap(loadOp.getResult()))
        {
            return {};
        }

        auto *ref = loadOp.getReference().getDefiningOp();
        return mlir::isa_and_nonnull<mlir_ts::PropertyRefOp, mlir_ts::ElementRefOp>(ref) ? loadOp
                                                                                        : mlir_ts::LoadOp();
    }
```

The chain of a read is the list of places from the read up to its root. From the read's reference,
take its base (`PropertyRefOp::getObjectRef`, `ElementRefOp::getArray`) and `rootOf` it. If that
is another place read, add its place and continue; otherwise it is the root. A root is one of:

- **a slot**: a `ts.Load` of an owning, uncaptured `ts.Variable`, or a `ts.Variable`'s ref
  itself (a value-type local such as an object literal). Its ends are `slotEnds(slot)`, plus every
  `ts.Retain` of a read of the slot and every owning `ts.Variable` declared from one: the root
  may move there.
- **owned**: a fresh value (`isFresh`). Its ends are its `ts.Release`s, and every user that is
  neither a borrow nor a view (`forEachUse`): a move.
- **not owned**: anything else - a block argument (a parameter, `this`), a global's load, a
  non-fresh call result, a merge. It has no ends here, but every call drops it.

The drops of a read, from the function's ops (collected once per function):

- a `ts.ReleaseSlotOp` whose operand is a `PropertyRefOp` with the position and result type of a
  chain place, or an `ElementRefOp` with the result type of a chain element place;
- an `ArrayPopOp`/`ArrayShiftOp`/`ArraySpliceOp`/`SetLengthOfOp` whose array's element type is
  the value type of a chain element place;
- the root's ends;
- a call (`SymbolCallInternalOp`, `CallOp`, `CallIndirectOp`, `CallInternalOp`,
  `CallHybridInternalOp`): every call for a root the function does not own; otherwise one with an
  operand derived from the root and not derived from the read. *Derived from x* is the forward
  closure over users' results with `mayPointInto`, stopping at call results: a call hands back a
  value it owns.

The read's uses are the `tryBorrow` walk from the read's result: views keep it borrowed, a
`ts.Retain` or a non-borrow use of the borrowed value is an escape (`reportBorrowEscapes` with the
place's description), and derived values' users are uses. Then, for each drop and each use, if
`reachableAfter(drop, use, read)`, report:

```cpp
    void reportPlaceBorrowOutlives(mlir::Operation *use, mlir::Operation *drop, llvm::StringRef name,
                                   llvm::StringRef place)
    {
        if (quiet)
        {
            return;
        }

        auto diag = use->emitError("'") << name << "' borrows " << place
                                        << " but is used here after it may be released or overwritten";
        diag.attachNote(drop->getLoc()) << "it may be released or overwritten here";
        signalPassFailure();
    }
```

`name` is `ownerName(read)` - the folded `const`'s name under `--di`. `place` is `'h.c'` when the
chain's first base has a name, with the field's name from the class storage (`getId(position)`),
or `'arr[]'` for an element; otherwise `a field` or `an element`.

Wiring:

- `checkValueMoves`: return `true` for a place read. It owns nothing, so there is no move to
  check.
- The retain loop: a retain whose value is a place read is skipped. `checkPlaceRead` reports it
  (Task 2: as an escape; Task 3: as a borrowing `let`).
- `runOnFunction`: after the candidates, call `checkPlaceRead` on every place read in the
  function. Short-circuit when the function has no drops at all.
