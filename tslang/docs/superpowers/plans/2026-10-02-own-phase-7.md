# `-mm=own` Phase 7 Implementation Plan: generators and async

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Under `-mm=own`, a generator compiles when its ownership can be proven (spec §2.7, §7
phase 7: "the state object as owner"). Today even `function* g() { yield 1; }` is an error, and
about 40 corpus files with a generator, an iterator object or a `.map`/`.filter` (which MLIRGen
builds as a generator) stop on one.

After this phase:

- A generator's **state object** is an ordinary owned block: its maker makes it and returns it,
  and its caller owns it like any other result.
- The generator's **locals** are fields of the state object. A store into one is a move into the
  container, a read is a borrow bounded by it, and reassignment releases the old value, as for any
  field.
- A **yielded value** leaves `next` in its result, which the caller owns.
- A **captured variable** of a generator (a parameter, an outer local) is a cell in a box that the
  state object holds: the escaping-closure rule of phase 5b, so a cell holding a number moves in
  and a parameter's object is an error (7b decides whether it can borrow).
- **Async** already works under own and gets its test.

**Architecture:** inference and signature passes only. MLIRGen does not change
(`test-own-mlirgen-matches-rc` keeps passing), and nothing new reaches the lowering in 7a.

**Tech Stack:** C++17, MLIR, CMake/ctest, `test/tester/test-runner.cpp`,
`test/tester/tools/measure.ps1`.

**Spec:** `docs/superpowers/specs/2026-09-24-own-memory-model-design.md`: §2.1 (the state object is
a mortal block), §2.7, §7. Results go into §18.

## Shapes (measured on 8cfb0f17)

- **The maker** `g` builds the initial state as a `ts.Constant` tuple
  `{".step", <locals>..., "next" = @<g>.next, ".captured"?}` in a `ts.Variable`, loads it, and stores
  it into `N = ts.New : !ts.value_ref<T>`. Then it does `O = ts.Cast(N) : !ts.object<T>`,
  `ts.Retain(O)`, stores `O` into its result variable and returns it. The state's release routine
  is generated from `T` and destroys every owning field and the `.captured` box (`tsrelcb_`).
- **The initial tuple** is `ts.Retain`ed before the store into `N` when `T` has an owning field (a
  local of class type). The constant holds `unit` there, so the retain holds nothing.
- **`next`** takes the state as `%arg0` and keeps it in a `ts.Variable`. Each local is
  `ts.PropertyRef(ts.Load(var), i)`, a store into it is a field store, and a reassignment is
  `ts.ReleaseSlot` + `ts.Store`, as for any field. A `yield v` stores `v` into the `{value, done}`
  result tuple, which rc `ts.Retain`s when `v` owns a block.
- **The caller** calls `next` through the state object:
  `ts.CallInternal(ts.GetMethod(F), ts.GetThis(F))`, `F = ts.Load(ts.PropertyRef(S, next))`. The
  signature pass does not resolve it, so the result is not fresh.
- **A captured variable** (a parameter, an outer local) is a captured `ts.Variable` cell, put in a
  box (`ts.Variable {captured, __capture_box}`) and `ts.RetainCell`ed. The box is stored into the
  initial tuple's `.captured` field, which goes into `N`. The frame's `ts.ReleaseCell` of the cell
  follows the `ts.Retain(O)`. The box has no frame release, so it moves into the state already.
- **Async** functions lower to an `async.execute` region whose locals are ordinary locals. The
  probe (a heap local across an `await`, a fresh object returned, a heap parameter read after an
  `await`, a string) compiles and runs under own, AOT and JIT, with gc's output, at 5.8 MB (gc
  6.1, rc 5.7, none 334.5).
- **An object literal with methods** is the same `ts.New`/`ts.Cast` to `!ts.object<T>` shape as
  the state object. The cast of one to an interface is `ts.NewInterface {__owned_result}`.

## Rulings made while planning

- **The cast of a `ts.New`'d `value_ref` to its `!ts.object` is a view** (`isView`): the same block.
  This is what makes the maker's result fresh.
- **`ts.NewInterface` is fresh only when the object it wraps is fresh and used nowhere else.** The
  object-literal interface cast marks it `__owned_result`, and `isFresh` read that mark as a block
  of its own. With the view above, `let raw = {...}; let i = <I>raw` would give `raw`'s block two
  owners (double free, found by the gate on
  `00object_annotated_method_extends_interface`). A class instance's `ts.NewInterface` has no mark
  and is unchanged.
- **The initial tuple's retain holds nothing.** A `ts.Retain` of a `ts.Load` of a `ts.Variable` whose
  initializer is a `ts.Constant`, and whose owning fields are never stored into, is erased.
- **A call of a generator's `next` resolves to it.** A function read out of field `p` of an object of
  tuple type `T` resolves to `@f` when, in this module, every `ts.Constant` of `T` holds `@f` at `p`
  and nothing stores into field `p` of a `T`. The call then gets that function's facts, and its
  result is fresh (`__own_fresh_result`). Cost if wrong: a fresh result that is someone else's.
- **A generator's capture box is an escaping closure's box.** `closureOfBox` learns the state
  object: a box stored into `.captured` of a tuple that goes into a `ts.New`. Phase 5b's rules then
  apply as they are: cells move in at the box's fill, the frame's `ts.ReleaseCell`s go, a frame
  use after is an error, and a parameter's heap cell is the 5b error.
- **Phasing.** 7a: tasks 0-4. 7b, a parameter's object borrowed by the generator (its result
  borrows the argument; a box that frees its cells but not their values) and the synthesized
  `.map`/`.filter`, is scoped from the corpus after 7a. One PR each.

## Review Focus

1. The view and `ts.NewInterface`: every block still has one owner. An object literal kept in a `let`
   and cast to an interface is an error, and a literal cast directly is one block.
2. `next` resolution: a field that can hold anything but the one function must stay unresolved.
3. The initial-tuple retain: erased only when nothing mortal can be in the tuple.
