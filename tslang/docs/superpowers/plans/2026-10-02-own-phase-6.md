## Findings that set the order

- **Script-mode globals are an rc fault.** In top-level code, `const t = new C()` stores into
  the global with no retain, and §9.30 then releases the value at the end of the block. 5ai fixed
  this for an assignment (`t = new C()`, via `isOwnedGlobalSlot`) but not for a declaration
  (`MLIRGenImpl.h`, the "not global scope" store). Own reads the store as a move and the release
  as a second reference, which is correct on wrong IR.
  - Under rc it is not observable today: nothing runs after `main`'s top-level code. A module
    with top-level code, imported as source, does not compile ("Global is referenced by
    parentless instruction! @puts"); with `-shared`, its exported `const` cannot be resolved.
    Those are two pre-existing bugs, every model, outside this phase.
- **"Left a retain behind" (8 files) is a global initializer region.** `const b: I = {...}` at
  module level builds a fresh value in the `ts.Global` region and retains it for
  `ts.GlobalResult`. No own pass runs there, so the lowering's guard fails the compile. It is
  loud, not a hole.

## Rulings

- **Globals.** A global is a root, and a fresh value moves into it. The retain for a
  `ts.GlobalResult` of a fresh value, or of a view of one, is erased. Anything else retained in
  a global region gets a named error, not the lowering's.
- **No block.** A `ts.Retain` whose root owns no block (a union or optional made from a number
  or null) is erased: an SSA value never changes.
  - A `ts.RetainSlot` is decided on its initializer's root, so it is erased only when nothing
    else is ever stored into the slot. `let y: number | string = 1; y = "s"; let z = y;` must
    stay an error, or move as it does today. Negative test and tooth.
- **Function literals.** A `ts.Cast` of a `ts.SymbolRef` to a function type holds no capture
  box, so it owns no block. The same slot guard applies: a slot that a capturing closure is
  later stored into is not covered.
- **Conversions.** A `ts.Cast` from a type that owns no block to `string` makes a fresh string.
  It already carries `__owned_result`; `isFresh` should read that.
- **String constants.** A `ts.Constant` string is immortal: retaining it takes nothing.
- **Tuple literals.** A `ts.CreateTuple` whose owning fields are constants or moved fresh values
  holds nothing of anyone else's, so rc's retain of it is its reference for the moves. This
  extends `holdsConstantsOrMoves` to a `CreateTuple` that feeds a `ts.CreateArray`, a store or a
  union.
- **Named messages.** A shape the dump recognises but this phase does not accept gets its own
  message in §5's language, not the catch-all, for example: `'x' is a conditional expression's
  result; -mm=own cannot prove which branch owns it yet`.

## Review Focus

1. Every erased retain is of a value that owns no block, is immortal, or moves into a root.
2. The slot guard: a `RetainSlot` decision on an initializer holds only if the slot is never
   stored again.
3. The rc change adds a retain under every counting model: the rc suite must stay unchanged. It
   does not branch on the model (§4.3), since gc erases retains.
